# SOC153 - Suspicious PowerShell Script Executed

## Alert Summary

A medium-severity alert was triggered after the execution of a suspicious PowerShell script on host **Tony (172.16.17.206)**.

The investigation focused on identifying the purpose of the executed script, its behavior, and any associated network activity.

---

## Alert Details

| Field | Value |
|---------|---------|
| Alert Name | Suspicious PowerShell Script Executed |
| Severity | Medium |
| Hostname | Tony |
| Host IP | 172.16.17.206 |
| Username | LetsDefend |
| File Name | payload_1.ps1 |

---

## Initial Triage

The alert indicated that a PowerShell script named **payload_1.ps1** was executed from the user's Downloads directory.

Initial objectives:

- Identify how the script was obtained.
- Determine what actions the script performed.
- Identify any external communication.
- Assess whether the execution was malicious.

---

## Investigation

### Script Download

Log analysis revealed that the script was downloaded using Google Chrome.

```text
https://files-ld.s3.us-east-2.amazonaws.com/payload_1.ps1
```

Location:

```text
C:\Users\LetsDefend\Downloads\
```

---

### PowerShell Execution

The script was executed by PowerShell using an Execution Policy bypass.

Observed command:

```powershell
powershell.exe -Command "
if ((Get-ExecutionPolicy) -ne 'AllSigned')
{
    Set-ExecutionPolicy -Scope Process Bypass
}
& C:\Users\LetsDefend\Downloads\payload_1.ps1\payload_1.ps1
"
```

Observation:

The script deliberately bypassed PowerShell execution restrictions before running.

---

## Verdict

### True Positive

The alert was confirmed as malicious.

Evidence showed that a downloaded PowerShell payload bypassed execution restrictions, communicated with external infrastructure, 
and uploaded files to a remote Tomcat server before triggering a deserialization-related action.

---

## Lessons Learned

- PowerShell execution should always be reviewed together with command-line arguments.
- Execution Policy bypasses are strong indicators of suspicious activity.
- DNS and network logs provide valuable visibility into script behavior.
- Downloaded scripts from user directories should be treated as high-risk until verified.
- Building a timeline makes it easier to understand the full attack chain.
